## Numerical Contracts and Fixtures

These checks describe the Phase 0 scaffold. The tiled renderer and `COVERAGE` reimport are documented in the [Phase 1 FITS contract](phase-1.md#render-and-export-contract).

- `PanelDescriptor` preserves dimensions, mono layout, filter, the `BUNIT` label, storage `BITPIX`, scaling, and mask provenance. Its local file fingerprint is byte length plus modification time in nanoseconds. WCS provenance reports whether the primary header supplied axis types. Geometry is validated separately.
- The reader accepts a local, uncompressed, two-dimensional image in the sole primary HDU. Extensions, including unhandled mask HDUs, and scaled 64-bit integer storage are outside this initial reader's scope. Decode raw storage with `raw × BSCALE + BZERO`, using float64 intermediates when scaling is needed and native float32 image buffers. A valid sample outside the float32 range produces an error.
- Validity comes from finite raw samples and the FITS integer `BLANK` marker. A missing sample has `valid=False` and a NaN payload. Finite negative, zero, and above-one samples retain their values. Tile buffers remain usable after the source handle is closed.
- Pixel coordinates are zero-based edge-exclusive regions with centers at integer `(x, y)` values. Arrays are indexed `[y, x]`, and the FITS header `CRPIX` is one-based. A tile includes its actual origin after the requested halo is clipped to the image bounds.
- [ADR-0002](adr/0002-surface-brightness-reference.md) records the initial surface-brightness convention. The Phase 1 export candidate uses float32 primary pixels, NaN for uncovered samples, a separate same-shape `COVERAGE` image with 0 or 1, and fresh output WCS. History will record processing and source provenance. An independent CFITSIO-based pixel reader and analytic TAN checks are candidates for export validation.

| Fixture | Expected outcome |
| --- | --- |
| Deterministic 16 × 12 scaled integer L-band panel | Raw values `4y + x − 15`, `BSCALE=0.5`, `BZERO=−2`, and `BLANK=−32768` at `(6, 4)`. A 5 × 4 synthetic cutout gives exactly 19 valid samples and a range of −4 to 4. |
| TAN at RA 359.999°, Dec 20° | One pixel east crosses RA zero. Agreement with an independent analytic TAN calculation within `1e-9` degrees and inverse round trip within `1e-8` pixels. |
| Uniform field and isolated Gaussian at 2 to 1 arcseconds per pixel | Uniform brightness 7.0 within `1e-10`. A Gaussian of source width σ = 3 pixels preserves integrated brightness to 1% after weighting by output solid angle. |
| Pseudo-unsigned integers, nonfinite floats, and unsupported storage | True zero, valid negative values, masks, overflow diagnostics, budget rejection before reading pixels, and post-close file release. |

These fixtures are generated by [the smoke job](../src/astromosaic/pipeline/smoke.py) and [numerical tests](../tests/numerical/). They establish starting tolerances for the named cases. Two-panel geometry, overlap, distorted WCS, injected faint structure, and large tiled workloads need their own fixture thresholds.

### Working Set

The reader checks each requested window plus its halo before reading pixels. The default 32 MiB allocation estimate reserves `64 × pixels + 512 × rows` bytes for section assembly, scaling, image and validity buffers, and per-row bookkeeping. The synthetic job limits the reader to 8 KiB and uses one explicitly spawned worker when requested. System page cache, library imports, other live tiles, and total process memory are outside this per-read estimate.

A single in-process run on Windows x64 with an Intel Core i5-14600K took 1.065 s including scientific imports and 0.008 s for a second run in the same process. Peak working set across both runs was 99.4 MiB. The OS file cache was uncontrolled. Phase 1 still needs an aggregate allocation and queue limit, with measured cancellation and cleanup. The figures describe the 16 × 12 mono fixture workload.

## Offline ASTAP Experiment

On Windows x64, ASTAP CLI 2026.11.01 with the D05 catalog solved a 55′ × 55′ POSS-II red cutout near M13 (`250.42°, 36.46°`). The solved WCS matched the cutout's reference pixel and differed from the archive header sky coordinate by 0.36 arcseconds. The source SHA-256 stayed unchanged. A source path with spaces and a Unicode character worked. A missing catalog and an enforced timeout both produced error exits. The process exited and scratch files were cleaned on timeout. The cancellation cleanup path is covered with a simulated interrupt.

The wrapper gives ASTAP a disposable FITS copy, one solver thread, and a local catalog. It checks the `.ini` and `.wcs` output together. The DSS sidecar retains original plate-model keywords, so the probe extracts the solved celestial WCS cards before interpreting them. It reports the solved reference position. Coverage across other fields, catalogs, and systems requires further trials. [ASTAP CLI documentation](https://www.hnsky.org/astap.htm#astap_command_line)

Download the [Windows CLI archive](https://sourceforge.net/projects/astap-program/files/windows_installer/astap_command-line_version_win64.zip/download), the [D05 catalog archive](https://sourceforge.net/projects/astap-program/files/star_databases/d05_star_database.zip/download), and the [MAST DSS cutout](https://archive.stsci.edu/cgi-bin/dss_search?v=poss2ukstu_red&r=250.42&d=36.46&e=J2000&h=55&w=55&f=fits&c=none). Keep them in local tooling or data storage. The cutout is from the Caltech/Palomar survey and is subject to the archive's image terms. [MAST DSS copyright information](https://archive.stsci.edu/dss/copyright.html)

## Desktop Probe and Packaging

The viewport uses a 2 × 2 signed `R32F` texture, a TAN rotation in a fragment shader, and a small CPU raster reference. Five pixel checks cover negative, zero, fractional, and above-one input samples plus uncovered output. The Windows OpenGL 3.2 probe recreated its context by reparenting the widget. It checked the 96 × 64 framebuffer at normal scaling and the 192 × 128 framebuffer with `QT_SCALE_FACTOR=2`. Forcing the Qt `offscreen` platform triggered the verified CPU raster fallback.

Use a fresh environment or sync the build group before each PyInstaller build. When pytest was installed, PyInstaller's Astropy hook entered optional plotting tests and aborted because Matplotlib was absent. Building with just `main,build` avoided that path. [PyInstaller one-directory mode](https://www.pyinstaller.org/en/stable/operating-mode.html)

```shell
poetry sync --only main,build
poetry run python -m PyInstaller --onedir --noconfirm --name astromosaic-cli --distpath dist --workpath build --specpath build --copy-metadata astromosaic src/astromosaic/__main__.py
poetry sync --only main,build -E desktop
```

Build the desktop bundle using the following command. On Windows, run it with a clean `PATH` during PyInstaller analysis. The first Windows bundle picked up an incompatible ICU DLL from an unrelated tooling directory on `PATH` and failed loading QtCore. The following clean build used Windows ICU and passed normal, high-DPI, and offscreen fallback probes.

```powershell
$venv = poetry env info --path
$previousPath = $env:Path
try {
    $env:Path = "$env:SystemRoot\System32;$env:SystemRoot"
    & "$venv\Scripts\python.exe" -m PyInstaller --onedir --clean --noconfirm --name astromosaic-viewport --distpath dist --workpath build --specpath build src/astromosaic/ui/viewport_probe.py
} finally {
    $env:Path = $previousPath
}
```

Run the CLI bundle with `smoke --spawn` and the viewport bundle with `--backend gpu` and `--backend cpu`. The default output location is `dist/`. Windows appends `.exe` to the commands.
